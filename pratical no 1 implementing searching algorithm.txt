Main Theory
Searching: Searching is the process of locating a required element, called the key, in a collection of data. The result indicates whether the key is present and, if found, its position. Searching is commonly used to retrieve information from lists, arrays, and records.
1. Linear Search
Linear Search checks each element sequentially, starting from the first element. If an element matches the key, its position is returned. If the end of the list is reached without a match, the key is reported as absent. It can be used on sorted as well as unsorted data and is easy to implement.

Algorithm:
1. Read the array, its size, and the key.
2. Set the index to the first element.
3. Compare the current element with the key.
4. If equal, report the position and stop.
5. Otherwise, move to the next element and repeat.
6. If all elements are checked, report “not found.”
Time complexity: Best case O(1), when the first element matches; worst case O(n), when the key is last or absent. It requires no extra search structure.
2. Binary Search
Binary Search works only when the data is sorted. It compares the key with the middle element. If they match, the search ends. If the key is smaller, the search continues in the left half; if larger, it continues in the right half. The process repeats until the key is found or the search range becomes empty.

Algorithm:
1. Set low to the first index and high to the last index.
2. Calculate mid = (low + high) / 2.
3. If the middle element equals the key, report its position.
4. If the key is smaller, set high = mid − 1; otherwise set low = mid + 1.
5. Repeat while low ≤ high; if the range becomes empty, report “not found.”
Time complexity: Best case O(1); worst case O(log n), because the search range is halved at each step.
Example
Consider the sorted array [10, 20, 30, 40, 50] and search for key 40.
- Linear Search: Compare 10, 20, 30, then 40. The key is found at the fourth position after four comparisons.
- Binary Search: The middle element is 30. Since 40 is greater, search the right half [40, 50]. The middle element is 40, so the key is found after two comparisons.
Comparison of Searching Algorithms
- Linear Search: Checks elements one by one; works on sorted or unsorted data; simple to implement; may require up to n comparisons.
- Binary Search: Repeatedly halves the search range; requires sorted data; efficient for large sorted collections; takes O(log n) time in the worst case.
Conclusion
Linear Search is suitable for small or unsorted collections because it is simple and does not require sorting. Binary Search is more efficient for large collections when the data is sorted. Therefore, the choice depends on the order and size of the data.
